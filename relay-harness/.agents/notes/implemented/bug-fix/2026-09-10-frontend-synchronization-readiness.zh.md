# Agent Note: 前端同步就绪状态与操作生命周期

Status: implemented

[English](2026-09-10-frontend-synchronization-readiness.md) | 中文

## 问题

保留的 Session 对象不能证明其历史已加载或连接仍然有效。重连后日志修订号不变，也不能让上一轮 Host 握手中的回执核验继续有效。资料库游标同样属于此前扫描，不能安全跨越新连接代次。此外，根工作流在执行命令之前安装 pnpm，命令的工作目录默认值不能替该动作定位嵌套项目清单。

## 决定

现有 Connection 服务独立于 Host 能力发布只读就绪数据源。每次成功读取描述的握手递增 epoch，连接消费者完成异步同步后阶段才变为 ready。停止、重连和同步失败都会撤回就绪状态。所有可能重入的发布点及迟到异步结果前后都有循环所有权检查。插件销毁时停止其持有的数据流。

Work 结合连接就绪、Session 历史打开状态和移除标记判断可用性。旧结果仍然可读，但两个数据源都就绪前不能打开或确认。回执核验按 Session、日志修订和握手 epoch 绑定，旧成功不能验证新代次。重连不会自动重试任何写入操作。

资料库保留未提交的搜索草稿，同步完成后只从第一页重查上次已提交的查询，不将旧续页游标带入新代次。旧查询和原生打开结果失去发布权限。已有来源身份去重和覆盖缺失记录仍限定在各自扫描内。

所有 pnpm 安装动作明确指定 `relay-harness/package.json`。免依赖仓库治理检查在安装前校验每个动作自身的块式输入。聚焦前端的工作流运行相关测试，不替代或削弱完整 CI 矩阵。

## 考虑过的替代方案

**从 Host 描述是否存在推断就绪。** 描述在消费者重读基线前到达，会允许用户在同步期间操作。能力与同步必须是独立的可观察事实。

**以已有对象或缓存回执为准。** 对象仍存在时，历史窗口可能尚未打开、正在加载、读取失败或被移除。此前握手的持久化核验不是新的核验。明确的就绪与 epoch 检查保留这些区别。

**重放所有待处理操作或保留资料库游标。** 重放命令可能重复已准入的写入，旧游标也可能指向已变化的语料。只有读侧刷新会自动重启，写入恢复仍需明确操作。

**在每个工作流中硬编码 pnpm 版本。** 这会在项目 packageManager 字段之外增加另一份版本来源。明确动作读取的清单路径可复用项目固定版本。

## 影响

不增加 Host 端点、授权策略、Session 事件或持久化任务存储。Connection 句柄新增客户端专用的必需可观察数据源，类型化夹具同步提供该字段。Work 与 Library 仍是侧栏页面。Ready 仅表示消费者同步已完成，不表示所有可选源都成功或两个下行连接已建立；Work 还要求自己的历史窗口打开。完整浏览器与构建产物检查仍不同于组件测试。

## 验证

连接测试覆盖同步待定、替换、停止、销毁、订阅者重入和迟到失败。Work 测试覆盖不可用历史与按 epoch 绑定的回执核验。资料库测试覆盖草稿保留、从首页重连、游标作废及旧响应。组装后的 Work 示例检查真实浏览器下行断线、操作禁用、恢复，以及没有隐式确认事件。工作流夹具拒绝位置错误的路径、以命令默认目录代替动作输入，以及借用其他动作的配置。
