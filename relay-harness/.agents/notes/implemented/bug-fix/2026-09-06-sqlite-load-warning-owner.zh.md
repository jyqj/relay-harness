# Agent Note：同步 SQLite 加载所有权

Status: implemented

[English](2026-09-06-sqlite-load-warning-owner.md) | 中文

## 问题

租约或 journal 适配器中的立即 SQLite 导入会在持久化适配器应用其初始化过滤器前发出实验性提示。即使没有数据库操作失败，CLI 消费方也会收到意外的 stderr。

## 决策

[SQLite runtime 工具包](../../../../packages/util/sqlite-runtime/README.md)负责唯一的同步缓存内置模块加载。它仅在该调用期间拦截完全匹配的 SQLite 稳定性提示，并在 finally 块恢复原警告发出器。连接与事务仍归适配器所有。

## 验证

冷启动子进程测试创建并查询真实数据库，导入租约与 journal 所有者，并检查无关实验性警告以及警告类型不同的同文消息仍然可见。内置模块加载失败的回归验证委托、恢复与可重试性。组装后的 CLI 与 ACP 快照保留空 stderr 断言。

## 曾考虑的替代方案

进程级警告屏蔽会隐藏无关诊断。依赖持久化适配器会倒置工具包所有权。异步过滤会使进程全局拦截跨越无关工作。

## 影响

SQLite 的实验性状态不变。工具包过滤的是初始化噪声，而非数据库失败；它不会串行化数据库写入，也不接管适配器生命周期。
