# Agent Note: Main workbench navigation and explicit record confirmation

Status: implemented

English | [中文](2026-09-14-main-workbench-navigation.zh.md)

## Problem

The product needs a main workspace for observing execution, resolving human input, and reviewing outputs while keeping Session navigation available. A sidebar summary cannot carry that workflow. Interface detail and unrestricted execution access also require different names, and a read-time enabled button must not contradict a Host-only root or quiescence requirement.

## Decision

Layout owns a transient main-navigation observable and a `shell.main` occupant. That occupant exclusively declares the resident `conversation` and keyed `shell.page` seats. Product Shell contributes Work and Library and a separate `sidebar.primary` navigation list; it does not replace the root or import other feature components. Hidden visited pages retain draft state but deactivate remote operations. Unknown or removed pages recover to conversation.

Work describes current Session facts rather than inventing a durable Task database. Attention navigates to the exact existing conversation for approval or questions; execution relationships navigate through the existing child addresses. Inactive children remain distinct from successful executions. Tool-recorded file paths are presented as changes and outputs, not verified final deliverables.

The Host supplies confirmation refusal reasons on the existing get response. Reads and maintenance-protected acceptance use the same pure policy over live root, turn, input, interaction, and background-job facts. The UI requires a current eligible read and a synchronized Session, while the Host still rechecks the write. Confirmation binds the reviewed transcript revision and is not a file-hash or test attestation.

An explicit inspector open dismisses the other inspector, and AppFrame gives that chosen inspector width priority. Main navigation dismisses inspectors and narrow navigation overlays. Session-addressed surface events are refused when their owner differs from the selected Session. Detailed view and Full access (high risk) have distinct labels; existing permission machine values and risk confirmation remain unchanged.

## Alternatives considered

**More sidebar cards.** This retains the loss of Session navigation and reserves the main area for chat regardless of the user's current operation.

**A separate frontend task database.** Current root Sessions and projections already provide the durable facts needed here. Duplicating lifecycle state would introduce reconciliation without supplying missing artifact-version or cross-workspace contracts.

**Unmounting inactive pages.** This makes navigation discard composer and query drafts. Resident pages with explicit activation instead preserve editing state while canceling hidden reads.

**Client-only confirmation predicates.** Duplicated root and quiescence rules drift from actual acceptance. A shared Host policy explains eligibility but never replaces the mutation's revalidation.

## Consequences

The existing plugin and Session ownership model remains intact. Main navigation is a viewing preference, not a new execution owner. A focused inspector can consume the center on narrow screens; main navigation restores the working area. A dormant page can retain memory, and page contributors must honor `active` for remote lifetimes. Navigation is transient and does not provide deep links or browser history integration.

Work is not an exhaustive global attention inbox. Background control verbs, immutable artifact review, provider repair, and full evidence-to-file navigation remain with their domains; this composition does not fabricate them. Browser and native file capabilities remain distinct.

## Verification

Framework-rendered component tests cover real slot ownership, navigation, draft retention, unregistration fallback, Session-addressed file requests, and inspector geometry. Host tests cover the shared eligibility policy and the real trusted Remote. The assembled keyless browser scenario covers main-area geometry, draft retention, output history and refusal, reconnection, source identity, and durable confirmation. Browser screenshots are generated by that runnable scenario; they are not substitutes for its assertions.
