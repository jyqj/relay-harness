# Agent Note：Chat 回收视口行并显式提供完整已加载历史

Status: implemented

[English](2026-09-05-chat-recyclable-history-window.md) | 中文

## Problem

仅扩大的尾部窗口能够限制初次渲染，但最终仍挂载全部已加载行。无条件移除行会丢失展开工具状态、文本选择与键盘焦点；浏览器查找无法搜索未挂载 DOM。行开始回收后，挂载行数也不能代表历史分页进度。

## Decision

Chat 复用已采用的 TanStack 变高虚拟器，按稳定的 Session 内节点键定位，测量行高并使用既有共享滚动容器。它双向回收，不删除已加载历史。既有底部跟随、前插锚点与语义重挂载规则仍由 ChatView 拥有；嵌套锚点记录所属节点以便虚拟恢复。切换 Session 清空交互与测量缓存。

展开工具、选中文本和键盘聚焦行会在交互持续期间保持键与挂载。保留数量可见，并明确附加在视口预算之外。完整已加载历史是显式模式，可通过控件或 Ctrl/Cmd+F 进入，为原生查找与长选择挂载全部已加载行。它不静默加载或声称搜索未加载历史；“加载更早”仍然可用。

已加载节点／Turn 诊断表示数据窗口，而非 DOM 占用。浏览器分页和性能探针使用该诊断；另设结构断言限制默认挂载集合加用户持有行。

真实浏览器分页约束暴露出第二个滚动 owner：虚拟器独立补偿分页和行测量，绕过 ChatView 的语义锚点记录。现在虚拟化只负责几何，ChatView 统一补偿测量提交，并在范围监听器运行前判断读者滚动。大幅跳转在新范围挂载后捕获语义位置。浏览器 2 像素容差不变；新增可控虚拟分页回归，修正后的真实浏览器验证仍需重新构建产物。

行内控件收到 pointer-down 或焦点时，会在虚拟化响应焦点前，将该行记录为阅读锚点。打开折叠内容也会退出尾部跟随状态，避免新展开的内容把控件从指针下移走。复制与分支保留原处理函数和原生副作用；浏览器验证检查真实剪贴板，不用伪造的成功写入替代。

## Alternatives considered

**继续扩大尾部窗口。** 重复分页后，DOM 仍随历史量增长。

**无条件移除所有屏外行。** 本地工具展开、活动文本选择与焦点都会消失。

**宣称原生查找覆盖虚拟列表。** 浏览器只能搜索已挂载 DOM。显式完整历史模式说明其已加载数据范围与刻意不限制的 DOM 成本。

## Consequences

聊天数据、输入语义与 Host 权威不变。用户保留行和完整历史模式是明确例外，并不声称任意用户操作下内存恒定。单元回归覆盖双向回收、分页、Session 重置、原生查找模式入口、选中文本和有状态工具展开。既有浏览器几何约束覆盖锚点与重新挂载；组装长交互场景和性能基准新增结构预算、原生查找／选择／工具检查。浏览器结果依赖最新构建产物，须与单元通过情况分开报告。
