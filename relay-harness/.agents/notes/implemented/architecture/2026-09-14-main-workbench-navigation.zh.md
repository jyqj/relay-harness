# Agent Note: Main workbench navigation and explicit record confirmation

Status: implemented

[English](2026-09-14-main-workbench-navigation.md) | 中文

## 问题

产品需要一个中央工作区观察执行、处理人工输入和审阅输出，同时保留 Session 导航。侧栏摘要无法承载这条流程。界面详细程度和不受限制的执行权限也需要不同名称；读取时显示可用的按钮不能与 Host 独有的根会话或安静状态要求矛盾。

## 决策

布局拥有临时主导航 observable 和一个 `shell.main` 占位组件。它独占声明常驻 `conversation` 和 keyed `shell.page`。Product Shell 贡献 Work、Library 和独立的 `sidebar.primary` 导航列表，不替换 root，也不导入其他功能组件。隐藏的已访问页面保留草稿，但停止远程操作；未知或被移除的页面恢复为 conversation。

Work 描述当前 Session 事实，不创建持久化 Task 数据库。待处理入口导航到精确的原有对话来审批或回答问题；执行关系通过已有子级地址导航。不活跃的子级与成功执行保持区分。工具记录的文件路径显示为变更和输出，不冒充已验证的最终成果。

Host 在原有 get 响应中提供确认禁用原因。读取和 maintenance 保护的确认共用纯策略，基于实时根身份、回合、输入、交互和后台 Job 事实。UI 要求当前可用读取和已同步 Session，Host 仍重新校验写入。确认绑定已审阅对话修订，不是文件哈希或测试证明。

显式打开一个检查区会关闭另一个，AppFrame 优先给被选择的检查区分配宽度。主导航关闭检查区和窄屏导航覆盖层。带 Session 地址的 surface 事件与当前 Session 不符时被拒绝。详细视图与 Full access (high risk) 使用不同名称；既有权限机器值和风险确认保持不变。

## 考虑过的替代方案

**继续增加侧栏卡片。** 这仍会丢失 Session 导航，并无论用户正在做什么都把主区域留给聊天。

**独立前端任务数据库。** 当前根 Session 和投影已经提供此处所需持久化事实；复制生命周期会引入对账，却没有补齐成果版本或跨工作区接口。

**卸载非激活页面。** 这会使导航丢弃输入框和查询草稿。常驻页面配合显式激活可以保留编辑状态，同时取消隐藏读取。

**仅客户端判断确认条件。** 复制根身份和安静条件会偏离真实确认。共享 Host 策略解释可用性，但不替代写入重新校验。

## 后果

既有插件和 Session 所有权保持不变。主导航是浏览偏好，不是新执行所有者。聚焦检查区在窄屏下可能占满中央区域；主导航恢复工作区域。休眠页面可能保留内存，页面贡献者必须遵守 `active` 的远程生命周期。导航是临时状态，不提供深链接或浏览器历史集成。

Work 不是穷尽全局的待处理收件箱。后台控制、不可变成果审阅、提供方修复和完整证据到文件导航仍属于各自领域；此组合不伪造这些能力。浏览器与原生文件能力仍有区别。

## 验证

框架渲染的组件测试覆盖真实 slot 所有权、导航、草稿保留、取消注册回退、Session 寻址文件请求和检查区几何。Host 测试覆盖共享可用性策略及真实可信 Remote。组装后的免密钥浏览器场景覆盖主区域几何、草稿保留、历史输出与拒绝、重连、来源身份和持久化确认。浏览器截图由此可运行场景生成，不替代其行为断言。
