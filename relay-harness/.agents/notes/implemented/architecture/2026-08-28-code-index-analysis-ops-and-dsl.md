# Agent Note: Code-index filter DSL, classified literal lane, and the cycles/dead_code analysis ops

Status: implemented

English | [中文](2026-08-28-code-index-analysis-ops-and-dsl.zh.md)

## Problem

After Phase 2 the search surface had three gaps the reference implementation had already closed. The query DSL parsed only `path:` — `kind:` / `lang:` / `name:` fell through as free text — so the model could not ask for a symbol kind or a language. The `literal_index` table stored verbatim strings with no retrieval face: no FTS mirror, no lane, nothing the ranking pipeline could consume. And `exploreGraph` answered only the structural questions (`relations` / `impact` / `tests`), leaving circular-dependency and dead-code questions — the reference's `graph_cycles.rs` and dead-code read model — unportable because the provider had no op to carry them.

## Decision

Close all three gaps in the search and provider layers, keeping the seam's request/result vocabulary the only cross-package contract:

- **Filter DSL** (`code-index-search/src/plan.ts`, `parseDslLite`). Four keys — `kind:` / `lang:` / `path:` / `name:` — with case-insensitive keys and quoted or bare values. Unknown `foo:` tokens stay free text; an empty value is consumed but unset; a repeated key keeps its FIRST value, a named divergence from the reference's last-write that keeps parity with the established `path:` behavior here. `kind:` normalizes through the reference's symbol-kind matcher, `lang:` filters on the parser's language name, and `name:` rides the rerank as a +0.25 bonus carrying the `dsl-name:` reason token.
- **Literal lane and schema v3** (`code-index-sqlite/src/ddl.ts`, `code-index-search/src/lanes.literal.ts`, `code-index-parser/src/languages/jsts/literal-classify.ts`). Schema v3 adds the `literal_fts` mirror over `literal` / `literal_kind` — trigger-maintained like `symbols_fts`, coalescing the nullable mirrored columns to `''` because FTS5 rejects NULL. The lane (weight `search.literal_weight`, default 0.9) runs bm25-ordered FTS5 `MATCH` and attributes each hit line to the chunk whose span owns it (`chunkOwningLine`: the last span starting at or before the line — spans may leave gaps, and the earlier chunk is the honest owner). JS/TS literals pass a priority-ordered classifier onto a nine-kind vocabulary (`route`, `url`, `topic`, `queue`, `env_key`, `config_key`, `sql`, `error_string`, `log_key`, confidence `0.92 × 0.85 = 0.782`); an unclassifiable literal is not recorded at all, the same gate the reference applies, and Python/Rust stopped emitting verbatim literal rows. The lane requires the port's optional `literalFtsCandidates` facet and disables itself without it, so pre-literal adapters keep working unchanged.
- **cycles op** (`code-index-local/src/cycles.ts`). An iterative Tarjan SCC pass over the file-import graph: only components of size > 1 count (a self-import is an SCC of size 1 and never surfaces), components order largest-first BEFORE the `max` cap so truncation always keeps the largest cycles with deterministic equal-size tie-breaks, severity follows the reference's file-granularity classes (`>= 5` high, `>= 3` medium, else low), and each component carries its witness edges — stored import rows whose both endpoints are members.
- **dead_code op** (`code-index-local/src/dead-code.ts`). Symbols with no incoming callers and no external references, found through a bounded scan of at most `min(40 × cap, 5000)` rows (the reference's adaptive scan budget), phase-1 filters (empty identity, entry-point names `main` / `__init__` / `__main__` / `setup` / `configure`, test-ish `test_*` / `Test*` prefixes) and phase-2 external-reference elimination. Every survivor reports `reason: 'no-callers'`; the default item cap is 50 and the op declares its `CALLS` / `REFERENCES` reverse lookups.
- **Edge projections completed.** Each op's explain envelope now declares the edge kinds it honored; cycles projects witness edges and the walked-edge rendering of `relations` / `impact` is unchanged, so every new answer keeps the property that each edge's endpoints resolve inside its `nodes`. The tool's `op` enum grew to five values with per-op `max` semantics (rendered nodes, test pairs, cycle components, dead-code items).

## Consequences

Schema version moved 2 → 3 on the literal mirror alone; the graph tier's write faces (delta transactions, `writeResolvedEdges`, test-edge rebuilds) are untouched. Literal coverage narrowed on purpose: a classified JS/TS-only lane beats a verbatim all-language index full of rows the classifier would have rejected. Cycle analysis is file-granular — the reference's package/community projections and their `critical` severity class stayed there. The vector tier's schema work ([the vector core](../feature/2026-08-28-code-index-vector-core.md)) and the heuristic-language widening ([heuristic languages and the context contributor](../feature/2026-08-28-code-index-heuristic-languages-and-context-contributor.md)) landed in the same phase; the five-stage incremental pipeline they all write through is owned by [the dirty-propagation note](2026-08-28-dirty-propagation-five-stage-pipeline.md), and the tool-face mapping by [the tools note](2026-08-27-code-index-tools.md).

## Alternatives considered

- **Follow the reference's repeated-key last-write** — rejected: the established `path:` behavior here was already first-match-wins; diverging per key would make one DSL behave two ways and surprise every caller that mixes filters.
- **Record every literal and attach the kind as a label** — rejected: the reference gates recording on classification because unclassifiable literals have no retrieval value; storing them anyway would bloat `literal_index` and `literal_fts` with rows no lane can rank meaningfully, and a later widening can re-admit kinds without a schema change.
- **Port the package/community cycle projections alongside the file granularity** — rejected: those projections need module clustering this provider does not compute, and their `critical` severity class belongs to that granularity; shipping file-level cycles first costs nothing later if a consumer shows up.
- **Compute dead_code by graph reachability (SCC or reverse-BFS) instead of a bounded scan** — rejected: the reference's scan-plus-filters pipeline bounds the read at `min(40 × cap, 5000)` rows with no transitive traversal, which keeps the op's cost proportional to the requested cap; a reachability sweep would couple the answer's cost to graph diameter the request cannot bound.
