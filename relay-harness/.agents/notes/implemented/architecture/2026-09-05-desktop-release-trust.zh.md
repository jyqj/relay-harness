# Agent Note: 桌面发行信任与源码检查

Status: implemented

[English](2026-09-05-desktop-release-trust.md) | 中文

## Problem

更新器若仅从仓库响应选择可执行文件，而不绑定本产品的发布者，就可能安装无关资产。可选的逐文件 JavaScript 检查也会让缺少 pragma 的生产入口不受检查。

## Decision

[桌面更新协议](../../../../apps/desktop/docs/trusted-updates.md) 从可选的已安装构建元数据派生信任。内置 Ed25519 公钥先验证 manifest 的精确字节，再解析内容。产品身份、release tag、稳定版本、到期时间、Windows x64 平台、NSIS 文件名、大小和 SHA-256 把签名绑定到一个安装器。HTTPS 主机限制、字节上限和总时限约束下载。安装前重新检查，下载后再次验证，再原子重命名和启动；失败清理临时文件。Renderer IPC 不提供信任或 URL。并发安装共享一次操作，每个进程最多启动一次安装器。

不伪造生产信任来源。缺少签名元数据、开发态启动和不支持的安装平台返回 `unavailable`，不下载或执行安装器。设置在非 `available` 状态禁用安装，并保留安装时的验证失败。发行页面链接仍只是信息入口。

所有已打包生产 JavaScript 源码启用 `@ts-check`。Renderer 声明从实际 preload API 派生，清单测试拒绝缺失 pragma 或新增排除项。两个不打包的发行 QA walker 仍排除。这扩展非 strict JavaScript 检查，不代表严格 TypeScript 覆盖。

下载操作拥有自己的重定向代次。退役一跳会关闭请求与响应；最终结算拒绝迟到回调。独立回归证明超时后的响应不能创建新网络请求，且已退役请求的错误不会终止有效的后继。

## Alternatives considered

- **信任原 fork 的最新可执行文件** —— 仓库身份不是本产品的发布者或资产身份。
- **使用未签名摘要** —— 响应攻击者可同时替换安装器和摘要，摘要必须签名。
- **把安装改成链接** —— 既未保留能力，也未诚实表达部署准备程度。验证协议存在，发布者配置缺失时仍不可用。
- **对难修文件关闭检查** —— 隐藏类型债务；具体 DOM、HTTP、进程、回调和结果类型保留检查。

## Consequences

协议支持 Windows x64 NSIS，但在真实发布者配置公钥和发行流水线之前，此处仍不可用。私钥不进入应用。测试使用临时测试密钥、假的 HTTPS 和启动器，不下载发行资产或运行真实安装器。生产 JavaScript 纳入类型检查，renderer 角色授权仍是独立运行时职责。
