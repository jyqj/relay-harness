# Agent Note: Code-index heuristic languages, SFC extraction, and the opt-in code-context recall contributor

Status: implemented

English | [中文](2026-08-28-code-index-heuristic-languages-and-context-contributor.zh.md)

## Problem

Phase 2's parser covered only the ten grammar-parsed language names. C#, PHP, Ruby, Swift, Kotlin, Dart, Scala, and Lua fell to the generic line-window tier — no symbols, no imports, no call edges — and Vue/Svelte single-file components were sliced as opaque text, so the graph tier's answers silently ignored a large share of real workspaces. On the consumer side the seam had exactly one consumer shape: the model had to decide to call `search_code_index`; there was no channel that pushed ranked index recall into a step the model was already working through.

## Decision

Widen language coverage with the reference's own fallback strategies and add the seam's first context-side consumer:

- **Spec-driven extraction** (`code-index-parser/src/languages/spec-driven/`). The eight grammar-less languages parse through per-language regex tables ported from the reference's `spec_driven.rs` — class and function declaration patterns, one import pattern, same-file call sites against `CALL_SITE_RE` with the shared `CALL_KEYWORD_BLOCKLIST` — at `heuristic` confidence 0.5. Declaration ends are estimated by scanning at most 200 lines forward for a closer, falling back 30 lines. Spec-driven languages extract no literals. The reference's C# `Environment.GetEnvironmentVariable` data-flow edges and its resolution-tier edge fields (callee uid, resolution kind/strategy) are explicitly out of this phase's record vocabulary.
- **SFC extraction** (`code-index-parser/src/languages/sfc.ts`). `vue` / `svelte` reuse the JS/TS grammars over each component's extracted `<script>` blocks — no dedicated wasm, and the parse reuses grammar binaries that already exist. The tier assignment is `heuristic` with a pinned 0.78: the reference `parse_sfc` hardcodes that confidence on its outcome, a named deviation from the heuristic default 0.5. The `event_emitter` dispatch kind is reserved for SFC template-event edges that no walker emits yet.
- **The tier matrix.** Twenty supported language names — nineteen distinct languages, since `jsx` shares the JavaScript grammar — in four assignments: `semantic` (0.85) for the JS/TS family, Python, and Rust; `tree-sitter` (0.7) for Go, Java, and C/C++; the two SFC names at heuristic-0.78; the eight spec-driven names at heuristic-0.5. `tierForLanguage` returns `null` for everything else, so unknown extensions still take the generic chunker.
- **The code-context contributor** (`packages/context/code-context`). Registration is strictly opt-in: a Loader entry with a config section registers one step-context contributor (`code-index-recall`) late-bound through `ctx.inject(['contextEngine'])`; an entry without one constructs `ctx.codeContext` but registers nothing, and the package ships in no bundle. For each claimed step the contributor joins the direct user messages' text blocks into one query — every distinct `@file` mention of the same text rides along as the explicit `paths` scope — and runs one ranked search over the seam, read through `ctx.get('codeIndex')` at execution time so the index stays optional. A healthy answer contributes one untrusted `## Code-index recall` message (hit lines in a fenced block, budgets applied in ranked order: `maxChars` 65536, `maxHits` 8, `minQueryChars` 8, clips on code-point boundaries recorded as `truncated`) plus one evidence record per injected hit whose `revision` is the answer's `indexEpoch` and one bounded coverage record. A no-hit step contributes a short bounded-negative message instead of silence; a degraded or failed search contributes nothing beyond a structured warning, so derived context can never masquerade as a legitimate "no results". Anti-recursion is structural: the query reads direct user messages only — injected recall text never feeds the next query — and the `form: 'recall'` source record is skipped by the session-query corpus extraction, keeping recall out of derived consumers.

## Consequences

Language coverage moved from ten names to twenty (nineteen languages); the generic tier is now genuinely the fallback for unknown extensions rather than the working tier for eight common ones. The regex heuristics carry the reference's blocklists and confidence pins, not grammar-grade precision — the trade is recorded in the subsystem doc's limitations. The contributor sits beside the tool consumer without competing with it: [the tool consumer](../architecture/2026-08-27-code-index-tools.md) answers questions the model deliberately asks; the contributor recalls context the model did not ask for, bounded and labeled as untrusted. Both consume the [seam scaffold](../architecture/2026-08-27-local-code-index-seam.md)'s late-bound resolution pattern. The DSL and analysis ops that share this phase's closeout are owned by [the analysis-ops note](../architecture/2026-08-28-code-index-analysis-ops-and-dsl.md); the vector tier underneath by [the vector-core note](2026-08-28-code-index-vector-core.md).

## Alternatives considered

- **Vendor eight more grammar WASMs for the spec-driven languages** — rejected: eight grammar artifacts (download pinning, byte-size locks, web-tree-sitter compatibility vetting each release) buy marginal precision over the reference's own regex tables for declaration-level extraction; the reference ships these languages spec-driven for the same reason.
- **Parse SFCs with a dedicated Vue grammar** — rejected: the `<script>`-block reuse keeps one grammar lineage for JS-family content; a dedicated wasm would drift from the JavaScript grammar it duplicates and add a release-pinning artifact for content the JS grammar already parses.
- **Enable the recall contributor by default** — rejected: every step would pay one ranked search's latency and output budget whether or not the deployment wants recall; the config section's presence is the switch, which keeps the shipped default byte-identical for deployments that did not ask.
- **Build the query from all step messages (assistant and context included)** — rejected: assistant turns contain the contributor's own injected recall text, so the query would recurse on its own output and drift from the user's intent; direct user text is the faithful per-step signal, and the `form: 'recall'` projection rule closes the second recursion path through derived consumers.
