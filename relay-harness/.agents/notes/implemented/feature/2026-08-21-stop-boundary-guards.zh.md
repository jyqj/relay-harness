# Agent Note: 停止边界守卫

Status: implemented

[English](2026-08-21-stop-boundary-guards.md) | 中文

## Problem

循环此前信任模型自己的停止决策。三类偏差会静默地结束轮次：空收尾回复（适配器未归类为 `EMPTY_RESPONSE` 的退化输出，例如纯空白文本）、在无工具调用轮次中产出围栏代码块（模型"描述"了执行而非真正执行）、以及收尾轮次没有任何验证性工具活动的完成声明。第四种情况是镜像：轮次在输出 token 上限处被截断，任务半成品收场，因为 `max-tokens` 是粘性的且没有任何机制覆写它。`guard/` 家族已有单次调用级卫生（重复检测、工具超时），但没有监视停止边界的能力，而这四类偏差恰恰在停止边界落定。

## Decision

两个新 guard 插件监听 `agent/turn-stopping`，按轮次收尾的 finish 种类划分管辖，监听器顺序因此不影响结果。`@relay-harness/rlh-behavior-correction` 只在普通 `stop` finish 上行动：检测三类偏差（检查顺序：空回复、未执行代码、未验证完成），并经 `agent.steer(...)` 向收尾轮次注入一条纠正消息，按轮次限界，空回复另有连续次数放弃机制。未验证完成检测要求收尾轮次零工具调用且更早轮次有工具活动，纯聊天会话永不被质疑。`@relay-harness/rlh-token-budget-controller` 只在 `max-tokens` finish 上行动：注入继续提示，由每轮 continuation 上限与收益递减检测（基于该轮次逐步 `outputTokens` 序列；未上报 usage 按产出充足计，仅由上限约束）双重限界。

两个插件都是边界上读取会话日志的纯函数——finish 种类、收尾 assistant 消息、每轮工具调用计数与 usage 全部来自事件——因此唯一自有状态是 `WeakMap` 中按 agent 隔离的内存计数，并明确文档化为不跨恢复保留。纠正走现有的持久 steer 通道（插件来源的 `user/message`），model-visible ⟺ logged 不变量无需新会话事件即可保持。

## Alternatives considered

- **一个插件管两种边界。** 两个决策面除扩展点外没有共性；拆成两个包让各自的配置与 README 保持准确，finish 种类划分也让组合顺序无关。
- **否决而非注入**（拒绝收尾步骤并强制重试）。否决会改写模型已产出的历史；注入保留偏差现场，让模型自我纠正，这正是提醒机制要训练的行为。
- **持久化计数。** 持久计数能跨恢复保留，但代价是新会话事件与 fork 语义；守卫是启发式提示，恢复后偶发的重复纠正比格式表面便宜。
- **硬迭代上限代替收益递减检测。** 只有固定上限时，产出近乎空输出的 continuation 仍在消耗预算；连续低产出检查恰好在 continuation 不再有用时停止。

## Verification

每个包都通过真实 agent loop 驱动脚本化 mock 适配器验证：各类偏差检测、检测抑制（有工具活动的轮次、聊天会话、两个方向的 max-tokens 串扰）、每轮与连续上限、新轮次的 continuation 计数重置、未上报 usage 的处理，以及配置的 fail-loud 校验。两个包均满足逐文件 100% 覆盖率门。

## Consequences

轮次不再能带着三类偏差或未完成的截断静默关闭；代价是每个插件每轮至多一条纠正消息，并由始终允许轮次关闭的上限约束。子代理经同一边界继承该行为，这是期望效果：被委托的轮次获得同样的卫生保障。部署方可通过 cordis.yml 按部署调节或关闭每个检测器，无需改动代码。
