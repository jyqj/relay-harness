# Agent Note: Code-index vector core — int8-quantized chunks_vec, the leased embed job queue, and the embeddings client

Status: implemented

English | [中文](2026-08-28-code-index-vector-core.zh.md)

## Problem

The epoch ledger declared `evidenceEpoch` as "reserved for semantic-evidence ingestion", but nothing wrote it — the second clock existed only so cache keys could be written correctly ahead of the tier it anticipated. Retrieval itself stayed lexical-plus-graph: a symbol renamed across a file, or a query phrased differently from the code, had no semantic recall path. And embedding generation could not simply run inside a refresh pass — the provider is slow, credential-dependent, and fails independently — so the tier needed durable decoupling before any of it could rank.

## Decision

Ship the storage, queue, and client core (schema v4), keeping retrieval wiring for [the full-link note](2026-08-28-code-index-vector-lane-full-link.md):

- **Two tables** (`code-index-sqlite/src/ddl.ts`). `chunks_vec` stores one int8-quantized embedding per `(chunk_id, model)`: the byte view of the quantized components in `q` (one byte per dimension; per the BLOB binding contract no scalar value ever passes through it), beside `scale`, the ORIGINAL float `norm` captured before quantization, `dim`, and a denormalized `chunk_rowid` so readers join rowid-aligned without a lookup — under a `format = 'int8'` CHECK and the same chunk-cascading deletion as every chunk-owned table. `code_embed_jobs` decouples indexing from generation: enqueueing is idempotent per `(chunk_id, model, content_hash)` plus the derived `dedupe_key` UNIQUE (`INSERT OR IGNORE` — a re-enqueue of identical text under the same model is a no-op, a content revision is a distinct job), a job cascades away with its chunk row so re-chunking purges stale jobs instead of leaving them to fail against replaced text, and `result_json` stays NULL by contract — a completed job's result IS its `chunks_vec` row, written by the drain inside the evidence-epoch transaction; only `usage_json` records the provider's `prompt_tokens` spend.
- **int8 quantization with a locked storage contract** (`code-index-search/src/vector-math.ts`). Symmetric per-vector quantization maps the input's largest absolute component to 127, keeping the representable range `[-127, 127]` instead of raw int8's asymmetric `[-128, 127]`. Ranking never materializes a dequantized vector: `cosineQuantized` computes `cosine = (scale · Σ query[i]·q[i]) / (|query| · norm)` directly over the int8 bytes, and its precision comes from accumulating exact small integers times float query components. Decoding renormalizes to the stored original norm — a no-op for ranking (cosine is scale-invariant) but the honest magnitude for callers consuming the vector itself. A result can exceed 1 by the quantization error; callers needing a strict unit interval clamp. `fingerprintVector` provides the stable cache-key form.
- **Embeddings client** (`code-index-local/src/embed/client.ts`). One OpenAI-compatible client per `(baseURL, apiKey, model)` over plain `fetch`, reusing the other direct-fetch adapters' attribution and bounded-read conventions. `embed` splits input into wire requests of at most `min(batchSize, maxInputsPerRequest)` (default 16) texts, arms every batch with the caller signal fused to a 30 s deadline, refuses replies over 4 MiB before parsing, validates record count, order, and dimensionality, and accumulates `usage.prompt_tokens` across batches for cost governance. Every failure maps onto one of five stable codes: `EMBED_RESPONSE_INVALID`, `EMBED_PROVIDER_ERROR`, `EMBED_INVALID_CREDENTIAL`, `EMBED_DIMENSION_MISMATCH`, `EMBED_ABORTED`.
- **Lease-guarded queue and drain** (`code-index-sqlite/src/embed-queue.ts`, `code-index-local/src/embed/worker.ts`). `claimEmbedJobs` claims due jobs atomically under `BEGIN IMMEDIATE` with `lease_owner` / `lease_until` (60 s default): expired leases are reclaimed, and a lease that expires on its FINAL attempt terminalizes `failed`. `completeEmbedJob` settles under an unexpired-lease guard; `failEmbedJob` returns the job to `pending` (terminal `failed` on the last attempt) with `last_error` and a retry instant (1 s default), spending the job's attempt budget. One drain walks claim → embed → quantize → commit → settle; each job commits inside its own evidence-epoch transaction, so N drained jobs advance `evidenceEpoch` exactly N times while `indexEpoch` stays frozen — the ledger's evidence clock is precisely the vector tier's revision counter. Drains are bounded by `maxJobsPerDrain` (256) and `maxPromptTokensPerDrain` (200000), and a deterministic misconfiguration refuses to burn the attempt budget: it stops the drain loudly instead.

## Consequences

`evidenceEpoch` has its writer family: the drain, one commit per job, never the refresh path. Re-embedding a `(chunk_id, model)` pair replaces its row; the upsert sits in the same evidence-epoch transaction as the completion settlement. The evidence clock now moves independently of content commits, which is exactly what makes [the retrieval wiring](2026-08-28-code-index-vector-lane-full-link.md) able to require it in cache keys without stalling content work. Cost governance starts per-drain (job and prompt-token budgets) with per-job usage records — no wall-clock or cross-run ceiling yet.

## Alternatives considered

- **Store float32 vectors** — rejected: four bytes per dimension plus no scalar columns sounds simpler, but the int8 storage contract costs one byte per dimension plus three REALs while `cosineQuantized` reads it directly with exact-integer dot accumulation; storing floats would quadruple the vector tier's footprint to save a decode step ranking never performs.
- **Fold the evidence clock into `indexEpoch`** — rejected: vector writes and content commits have different lifecycles (embedding is slow, retryable, and fails independently of the workspace tree); one clock would advance the content epoch on every drain, invalidating every chunk-text cache entry for bytes that never changed.
- **Keep the job queue in process memory** — rejected: a crash would drop pending jobs with no ledger of what was owed; the durable queue is what makes idempotent re-enqueue, chunk-cascade cleanup, and lease-expired reclaim across restarts possible at all.
