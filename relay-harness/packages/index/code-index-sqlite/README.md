# `@relay-harness/rlh-code-index-sqlite`

English | [中文](README.zh.md)

SQLite storage repository for the local code-index capability: the derived, disposable on-disk medium behind `ctx.codeIndex`. The package owns the storage lifecycle end to end — fail-closed admission of database files (rebuilding an admitted-but-mismatched store in place), the chunk-text codec over the `(text_encoding, text)` column pair, exactly-once epoch commit wrappers for both clock channels, the incremental file-delta writer, the int8 vector tier with its embedding job queue, an LRU decoded-text cache, and the read-side retrieval adapter the ranking engine consumes. Scan/diff orchestration, ranking, and everything model-facing belong to the provider and consumer packages; none of that lives here. This package registers no service, mounts no plugin entry, and exposes no Config.

## Storage Layout

Schema version 8 (`CODE_INDEX_SQLITE_SCHEMA_VERSION`, `src/ddl.ts`) keeps the chunk/graph/literal tiers and zstd chunk codec, then replaces model-only vector identity with durable `embedding_generations`, generation-keyed jobs/vectors, and a separate embedding clock, all ported or trimmed from the reference implementations' index and memory schemas:

- `metadata` — key-value ledger for cross-restart scalars; the three clocks (`index_epoch` / `evidence_epoch` / `embedding_epoch`) are seeded at `'0'` and survive reopening, and per-file export fingerprints live under `export_fingerprint:<filePath>`, where the delta writer replaces the value on every string write, clears the entry on `null` (an emptied export surface), and leaves it untouched on `undefined`. `src/epoch.ts` owns all three clocks: `bumpIndexEpochOnceInTx` folds one counter advance into every content transaction as its final pre-COMMIT statement, `bumpEvidenceEpochOnceInTx` reserves the runtime-evidence channel while `bumpEmbeddingEpochOnceInTx` advances vector-materialization batches, `readEpochs` refuses missing or unparsable ledger rows instead of re-zeroing them, and `assertExactAdvance` audits a commit against the declared channel (`epoch_rules.rs` semantics): the declared clock advances exactly once and the sibling stays frozen.
- `files` / `chunks` — STRICT row sources; chunks reference their file with `ON DELETE CASCADE` and carry `chunk:<file>:<index>` identifiers. Column positions mirror the reference layout.
- `chunks_fts` / `files_fts` / `file_paths_fts` — FTS5 over chunk text and file summaries (`unicode61 remove_diacritics 2`) plus trigram path lookup. Application maintenance follows the reference rule implemented in `src/writer.ts`: mirror deletes resolve doomed rowids through their base tables BEFORE those rows disappear, inserts re-mirror under the base row's own rowid (`lastInsertRowid` of the outermost statement survives trigger inserts), and only `file_paths_fts` heals itself through triggers alone.
- `symbols` (+ `symbols_fts` trigram mirror), `imports`, `symbol_refs`, `call_edges`, `test_edges`, `literal_index` (+ `literal_fts` mirror over `literal` / `literal_kind`, v3) — STRICT graph rows, each file-owned table cascading from its `files` row. `symbols_fts` maintains itself through insert/delete/update triggers; the writer still deletes `symbols` rows explicitly ahead of the cascade, and the cascaded delete then removes zero rows (never a double delete). `literal_fts` (`unicode61`) heals itself through the same trigger pattern, coalescing the nullable mirrored columns to `''` because FTS5 rejects NULL column values. `test_edges` are path pairs rather than file-owned rows, so file removals leave them; the metadata fingerprint entry is the writer's per-file cleanup. All graph columns were trimmed to what the graph read face consumes. Two write faces serve the graph tier beyond the file delta: `writeResolvedEdges` (`src/writer.ts`) replaces only a file's `call_edges` / `symbol_refs` row sets for dirty re-resolution, and `src/test-edges.ts` owns the path-pair rebuilds (`rebuildTestEdgesForFiles` heals the changed endpoints in one epoch-bumped transaction, `rebuildTestEdgesFull` recomputes every pair in memory) with the shared stem-fragment/LIKE matching semantics of `testStemCandidateFragments`.

The vector tier stores one int8-quantized embedding per `(chunk_id, generation_id)` in `chunks_vec`; `embedding_generations` records provider/endpoint/model/dimension mode/normalization/quantizer/chunker identity so compatible vectors coexist and coverage is generation-specific — the byte view of the search package's quantized components in `q` (one byte per dimension; scalars never pass through the BLOB), `scale`, the ORIGINAL float `norm`, `dim`, and the denormalized `chunk_rowid`, under a `format = 'int8'` CHECK and a chunk-cascading foreign key. `writeChunkVectors` (`src/writer.ts`) upserts a batch inside one embedding-epoch transaction, so one drained batch advances `embedding_epoch` exactly once while `index_epoch` and runtime `evidence_epoch` stay frozen; re-embedding a pair replaces exactly that pair's row, and a row whose `q.byteLength` contradicts its `dim` aborts the batch (`CODE_INDEX_VECTOR_ROW_INVALID`). Encode/decode math lives in `@relay-harness/rlh-code-index-search/vector-math` (`quantizeInt8` / `dequantizeInt8` / `cosineQuantized`); storage only enforces the contract.

The embedding job queue (v4, `code_embed_jobs`, `src/embed-queue.ts`) decouples chunk indexing from embedding generation. Enqueueing is idempotent per `(chunk_id, generation_id, content_hash)` (plus the derived `dedupe_key` UNIQUE) via `INSERT OR IGNORE`, and each job cascades away with its chunk row, so re-chunking a file purges stale jobs instead of leaving them to fail against replaced text. `claimEmbedJobs` claims due jobs atomically under `BEGIN IMMEDIATE` — expiring leases reclaim, and a lease that expires on its final attempt terminalizes `failed` — while `completeEmbedJob` records `usage_json` under an unexpired-lease guard and `failEmbedJob` returns a job to `pending` (or terminal `failed` on the last attempt) with `last_error`, a retry instant, and optionally the spend already billed before the failure (`usage`, merged into `usage_json`). `result_json` stays NULL by contract: a completed job's result IS its `chunks_vec` row. `pendingEmbedCount` reports one generation's backlog; terminal failures whose current source hash still matches receive one durable `reconcile_resets` reset through `resetFailedEmbedJobsForGeneration`, preventing both permanent silent holes and infinite retries; `embedChunkInputs` batch-reads decoded chunk text plus rowid for the drain.

Admission (`src/open.ts`) refuses foreign databases loudly (`CODE_INDEX_DB_FOREIGN_APPLICATION`): a non-zero foreign `application_id`, or user tables under no registered id, reject the file untouched. An admitted store carrying an out-of-range version or unrecognized tables rebuilds in place instead of migrating — every table here is reconstructable derived data, so bytes win over compatibility shims. Missing directories and files are created owner-only (`0700`/`0600`); failing handles close before the error propagates. Opened handles run with `foreign_keys = ON`, a 5 s `busy_timeout`, and the caller's journal mode.

The codec (`src/codec.ts`) registers two encodings over the `chunks` TEXT pair. `'plain'` stores the text verbatim; `'zstd'` stores a Zstandard level-3 frame as base64 text, so the payload keeps the column's TEXT contract and readers plus the embedding drain always decode through the codec. The encoder follows the reference policy: payloads of at most 128 UTF-8 bytes stay plain, larger candidates compress, and a frame that does not shrink below the original bytes falls back to plain. Readers refuse to guess: an unrecognized stored tag, or a `'zstd'` payload that fails to decompress, throws `CODE_INDEX_SCHEMA_VERSION_UNSUPPORTED`. The `chunks_fts` mirror always receives the decoded text, so search matches plaintext regardless of how the base row is stored. Writer input is caller-generated parse output (`FileUpsert`: summary, excerpt, parser tier/confidence, test flag — produced by the provider's scanner, not invented in storage).

The reader (`src/reader.ts`, `createRetrievalPort`) implements the search package's `RetrievalPort` over raw SQL: bm25-ordered FTS matching with the ported column weights, structured scope filters rendered as WHERE clauses (LIKE metacharacters escaped; the language clause tests `files.language`, so the `lang:` DSL scope is enforced in SQL), recency-ordered grep scans (`rowid DESC` when no file scope pins cardinality) streamed with per-row lazy decoding, bm25-ordered literal matches through `literal_fts` (`literalFtsCandidates`), and batched detail fetches. Symbol-token lookups (`symbolNamesByTokenSubstring`) and the `graph` facet (`createGraphReadFacet`: symbol seeds, exact-name and uid resolution, per-seed-capped caller/callee edge windows, degrees, chunk spans, imports, complete per-file edge reloads, importer reverse lookup, resolved re-export targets, impacted tests, fingerprints, literals) read the graph tier — seeds come from `symbols_fts` trigram LIKE with case-insensitive exactness leading, per-seed edge caps run as `ROW_NUMBER()` windows, and every id list is deduplicated, sorted, and batched through `IN (...)`. Store-side duties stop at ordering, scoping, and decode-on-demand; scan budgets stay on the search side, per the port's contract. Only visited rows pay for decoding, and each decoded text lands in the LRU cache (`src/cache.ts`) whose slots key on `(index_epoch, chunks.rowid)` — any commit invalidates naturally. Cache capacity is this package's own decision, scaled by repository-size tier: 128 / 256 / 384 / 512 entries for tiny / small / medium / large (`chunkTextCacheCapacityForTier`). Degraded read results never enter: cache writes accept only callers holding a freshness pair.

## Errors

Stable codes route failures programmatically; never parse messages.

| Code | Raised when |
|---|---|
| `CODE_INDEX_DB_FOREIGN_APPLICATION` | The database belongs to another application: foreign `application_id`, or user tables under no registered id. |
| `CODE_INDEX_SCHEMA_VERSION_UNSUPPORTED` | The derived medium carries state this layer does not register: an unknown `text_encoding` tag, a `'zstd'` chunk payload that fails to decompress, a lost or hand-edited epoch ledger row, or an audited commit that violates the declared epoch rules. |
| `CODE_INDEX_VECTOR_ROW_INVALID` | A `writeChunkVectors` row violates the storage contract: its `q.byteLength` contradicts its declared `dim`. |

## Model Experience

Indirectly, through the `search_code_index` and `code_index_status` tools whose ranked hits the provider reads out of this store.

#### KV Cache effect

None; this repository shapes which records exist and how chunk text decodes, but never enters a request prefix itself.

## Known Limitations and Deferred Work

- **Rebuild discards acknowledged state** — an admitted store with a drifted version or inventory wipes derived content (including committed epochs) without prompting, which is correct for derived media but means the surrounding provider owns durable-source recovery.
- **Synchronous statements** — `DatabaseSync` blocks the JavaScript thread while a statement executes.
